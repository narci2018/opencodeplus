### 4. Phase 2: 核心适配（已完成）

> 关键转折：放弃虚构的 `definePlugin/registerAgent` 假 API，改为使用 **opencode 真实插件 API**——`Plugin.define({ id, async setup(ctx) })` + `ctx.agent/skill/tool/command.transform(editor => ...)`。源码参考：`packages/plugin/src/promise/plugin.ts`、`packages/plugins/figma/index.ts`。

#### 4.1 插件主入口重写（`plugin.ts`）

- **注册 agent**：`ctx.agent.transform` + `Agent.Name.make('TRAE 宝')`，`mode='primary'`，`native=false`
- **注册 3 个技能**：`ctx.skill.transform`（TRAE-browseruse / TRAE-code-mode / TRAE-computer-use）
- **注册 4 个 Chronicle 工具**：`ctx.tool.transform`，用 `input` JSON schema（注意：不是 `parameters`），含 chronicle_status / chronicle_recent / chronicle_search / chronicle_get_memory
- **注册 1 个命令**：`ctx.command.transform`（trae-bao.toggle，浮动宠物开关）
- **助理系统**：`AssistantManager` 构造时注入 `ctx.session`，可创建真实 opencode 子会话
- **IM Bridge / 浮动宠物**：按配置懒加载，返回 `async () => {...}` 清理函数
- **清理函数**：统一 dispose 助理、IM 桥接、浮动宠物、记忆系统

#### 4.2 浮动宠物 → TUI 适配（`src/floating-chat/floating-chat.ts`）

- opencode 无 Electron 窗口 API，改用 TUI：`ctx.keymap.layer({ commands: [{ id: 'trae-bao.toggle', bind: 'alt+shift+space', run }] })`
- 面板开关：`ctx.ui.panel.open('trae-bao', { presentation: 'panel' })` / `ctx.ui.panel.close()`
- `FloatingChatHandle` 增加 `openPanel()/closePanel()`；`sendChannels/receiveChannels` 改为 `Set<string>`

#### 4.3 IM Bridge → ESM 修复（`src/im-bridge/im-bridge.ts`）

- `__dirname` 在 Bun ESM 中为 undefined，改用 `fileURLToPath(new URL('.', import.meta.url))`
- `spawnBridge` 返回 `ChildProcess | null`，接入处用 `?? undefined` 归一化

#### 4.4 Chronicle → Windows OCR（`src/chronicle/chronicle.ts`）

- 新增 `loadOcr()`（懒加载 tesseract.js worker）、`captureAndOcr()`（screenshot-desktop + tesseract）
- `persistObservation()`：Buffer 类型分支处理（string path 直接读，Buffer 直接用）
- `startCaptureLoop()/stopCaptureLoop()` + 10 分钟/6 小时摘要窗口，`pause/resume/dispose` 接入循环

#### 4.5 双助理系统 → opencode 会话（`src/agent/assistant.ts`）

- 修复 `Throttler.queue` 属性/方法冲突 → 重命名私有属性为 `tasks`
- 新增 `dispatchPrompt()`：`ctx.session.create()` 建真实子会话 → `ctx.session.prompt()` 注入提示词
- 新增 `getSessionProgress(sessionID)`：查询会话进度
- `createAssistants` 传入 `session: ctx.session`，助理可驱动真实 agent 运行

#### 4.6 验证结果（全部通过）

- **typecheck**：`bun run typecheck`（插件根目录）0 错误
- **冒烟测试**：
  - plugin.setup 注册 agent 1 / skills 3 / tools 4 / command 1 ✓
  - Chronicle 生命周期（录制/暂停/恢复）✓
  - dispatchPrompt 降级路径 + 会话路径 ✓
  - 浮动宠物 TUI keymap/panel ✓
  - IM Bridge 子进程 spawn（wx + feishu）✓

#### 4.7 关键发现：opencode 内置 trae agent

- `packages/core/src/plugin/trae/trae.ts`：opencode **已内置** `opencode.trae` 插件，注册 agent `trae`（native=true, mode="all"）+ computer-use MCP
- 内置 system prompt（`packages/core/src/plugin/trae/system.md`）：Code Mode `execute` 工具 + `tools.browser.*` + `tools.computer_use.*` + 工作规则 + 安全约定
- **结论**：`trae-bao` 与内置 `trae` 互补——内置 trae 提供 Code Mode/浏览器/桌面自动化编排，`trae-bao` 提供浮动宠物、IM 桥接、跨会话记忆、双助理系统

## 已知限制

| 限制 | 影响 | 解决方案 |
|------|------|---------|
| Chronicle 仅 macOS | Windows 无法使用原生屏幕捕获 | tesseract.js + screenshot-desktop |
| 3D 宠物模型 710KB GLB | 插件体积增大 | 按需加载（Lazy Load） |
| 飞书 OAuth 需要字节账号 | 无法在 opencode 独立使用 | 提供自定义 API 配置 |
| IM Bridge 子进程 2.5MB | 启动延迟 | 按需启动（Lazy Spawn） |
| 浮动宠物需要 GUI | headless 环境不可用 | 自动禁用，仅 TUI 模式 |
| 动态配置来自云端 | 本地无法获取 | 提供本地配置文件 |
| **真实插件加载** | opencode 需要从 config 加载插件 | 需在真实环境注册并验证 agent 出现 |
